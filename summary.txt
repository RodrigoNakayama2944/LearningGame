WHAT THIS IS
------------
A CSS puzzle game ("CSS Quest") that teaches HTML/CSS basics with a live
preview like Flexbox Froggy. The game is FOCUSED ON FLEXBOX (display: flex),
since flexbox is the most important layout skill. Built with Vite (simple
HTML/CSS/JS, no React) and deployed on GitHub Pages.

REPOSITORY
----------
- Repo: https://github.com/RodrigoNakayama2944/LearningGame.git

- Live site: https://RodrigoNakayama2944.github.io/LearningGame/
- Deployment: GitHub Actions auto-builds and deploys on every push to main
  (.github/workflows/deploy.yml). Pages source must be "GitHub Actions".

GAME FEATURES
-------------
- 20 levels in src/levels.js (all flexbox), split into 5 worlds of 4 levels
  (bosses at levels 4, 8, 12, 16 and 20)
- Editor with line numbers + live preview iframe (updates on every keystroke)
- Target iframe showing the goal (uses level.solutions[0].css)
- Hint box, Check Answer, Reset, Show Hint and CSS Tags buttons (there is NO
  "Show Answer" button: the student has to solve the level by themselves)
- Language button (top right): opens a menu with English and Português
  (BR). The choice is saved in localStorage ("cssquest-language") and the
  whole game switches instantly: interface text, level titles, hints,
  descriptions, the "How it works" explanations, the CSS Tags guide and
  the result banners. CSS code, CSS values and the validation rules stay
  the same in every language.
- Dracula theme throughout (bg #282A36, cyan #8BE9FD, green #50FA7B ...)
- "Next Level ->" green button (no auto-advance)
- CSS Tags modal (replaces the old "CSS Reference" modal): a clickable
  guide with 26 CSS properties grouped in Layout, Flexbox, Box model and
  Color and text. Every tag is a button: clicking it expands a panel with
  what the property does, the most common values and a code example.
  Clicking it again collapses it. The modal closes with the X, by clicking
  outside or with the Esc key, and it also closes when the level changes.
- Some levels have more than one valid solution (when they apply). The
  validation always uses geometry, so different CSS that produces the same
  layout is accepted (level 10 accepts margin-top: auto or space-between).
- After solving a level, a "How it works:" panel appears in the LEFT column
  (below the buttons) with one entry per element (HTML selector or CSS
  property) explaining what it does, plus a "Key idea:" tip at the end.
- The explanation panel has two small buttons in its header:
  ▾ shrinks it to the title only (▸ expands it again) and ✕ removes it.
- The celebration (particles, screen flash, "Correct!" stamp) happens only
  ONCE per level visit. Pressing "Check Answer" again on a level that was
  already solved keeps the banner and the explanation, with no new effects.
- The explanation shown after solving matches the answer the student wrote
  (a Grid answer on level 6 gets the Grid explanation).

GAME LAYER (STARS, XP, MAP, ACHIEVEMENTS)
-----------------------------------------
- Stars: every level gives 1 star when solved, +1 when no hint was used and
  +1 when the run had at most one wrong check (3 stars maximum). The best
  result is stored, so replaying never lowers a previous score. Reset only
  restores the starter CSS; it does not restore hint/wrong-check counters,
  because each level visit starts a fresh run.
- XP and ranks: 10 XP per star, 60 stars and 600 XP maximum. Ranks are
  Novice (0), Apprentice (60), Stylist (180), Flexbox Knight (330),
  Flexbox Master (480) and Legend (600), shown in the top header.
- Sequential unlocking: level 1 is always open; every other level needs the
  previous one solved. Locked levels show a lock on the Quest Map.
- Quest Map modal: two tabs. "Levels" shows the 5 worlds, per-level stars,
  best time, current level and a Daily Challenge card. "Achievements" shows
  all 16 badges (world clears, speed, daily streak, linguist, perfectionist,
  boss slayer, quest complete and others). A reset-progress button also lives
  in this modal.
- Daily Challenge: picks a solved level based on the local date, disables
  hints and tracks a day streak. It does not add a separate XP reward.
- Boss levels show a short intro overlay before play. The final level opens a
  completion overlay with total stars, XP and rank.
- Sound effects are OFF by default for classroom use. They use the Web Audio
  API with generated tones (no audio files) and can be toggled in the header.
- Progress is stored in localStorage under "cssquest-progress-v1". The
  versioned key lets the save format evolve without crashing old saves.
- Every new UI string, achievement and level 13-20 exists in English and
  Portuguese (pt-BR).

HIDDEN DEV TOOL
---------------
- Press Ctrl+Alt+Shift+D anywhere to open it (or press the shortcut again to
  close it). A password is required: the password is "deadlock".
- The password is compared against an FNV-1a hash in the client, so it is not
  stored as plain text. This is a classroom convenience, not real security:
  anyone with access to the source can modify the client.
- After unlocking, the panel shows the current level title and its answer
  CSS. Levels with more than one solution show one button per solution.
  "Fill editor" copies the selected answer into the editor. The unlock lasts
  for the current page session and resets on reload.
- The tool is intentionally not linked anywhere in the interface.

NEW LEVELS (7 -> 12) - WHAT WAS ADDED
-------------------------------------
- Level 7 (flex-grow): three bars share the row; the purple one must be
  exactly twice as wide as the other two. The validator checks the
  computed flex-grow values AND the real width ratio.
- Level 8 (space-between): four buttons must be spread across the row with
  equal gaps and touching both edges. The validator compares the three gaps
  and the distance to the edges.
- Level 9 (align-self): the container keeps align-items: center, but only the
  purple box goes to the bottom. The validator checks that the other two
  boxes are still centered.
- Level 10 (margin-top: auto): the footer is pushed to the bottom of a
  column flex container. justify-content: space-between is also accepted,
  because the validation is done with geometry, not with the CSS text.
- Level 11 (flex-shrink: 0): the button must keep the width of its text while
  the long bar shrinks.
- Level 12 (nested flex): the header needs display: flex so gap and
  align-items start to work (avatar and title text side by side).
- Every new level also has the Portuguese text (title, description, hint,
  starter comments, explanations and tip) in src/levels-pt-BR.js.
- The old horizontal level-dot navigation was replaced by the Quest Map
  modal, which also shows stars, best times and the sequential lock state.

LEVELS 13-20 - WHAT WAS ADDED
-----------------------------
- Level 13 (align-content): six tiles wrap into lines; the lines must be
  spread from the top to the bottom of the board. The validator checks the
  computed flex-wrap, the real line positions and the row gaps.
- Level 14 (flex-basis): side panels start at 25% and the main panel at 50%,
  without growing or shrinking. The validator requires a computed flex-basis
  different from auto and a real 1:1:2 width ratio; width-only answers fail.
- Level 15 (space-around vs evenly): the starter uses space-evenly; the
  answer needs space-around so the outer gaps are half of the inner gaps.
  Tag sizes were reduced so the target fits narrow previews without overflow.
- Level 16 (boss): six cards wrap into at least two rows with the same
  starting width and spread lines. The validator checks three columns,
  equal widths, the gap math, line spread and no horizontal overflow.
- Level 17 (auto margins): margin-left: auto pushes the actions group to the
  right while the logo stays left. justify-content: space-between also passes
  because the validator uses geometry.
- Level 18 (row-reverse): the whole row must reverse visually. The validator
  requires the computed flex-direction to be row-reverse; an order-only
  solution fails on purpose.
- Level 19 (min-width: 0): the long label shrinks, clips with an ellipsis and
  keeps the counter inside the card. The validator requires computed
  min-width 0, a clipped label and a visible counter.
- Level 20 (final boss): app column, topbar row with space-between, layout
  row with a fixed sidebar and a growing content area, and a footer at the
  bottom. The validator checks each nested flex container and the geometry
  of every section.

IMPORTANT FIXES / DECISIONS
---------------------------
- All level items are tags with text (no empty pixel-sized boxes). Item sizes
  come from their content and padding; containers use relative units and
  min-height instead of fixed pixel dimensions.
- Pixel-based goals were removed from the level descriptions, hints,
  explanations and validators. The puzzles now ask for relationships such as
  "twice as wide", "same space" and "centered", not exact pixel values.
- Visual consistency pass: every painted item uses border-radius: 0.5rem
  (the level 12 avatar is a rounded badge, not a 50% oval). Level 4 already
  provides gap, level 5 requires the order property, level 6 requires the
  cards to fill each row, and level 11 shows an ellipsis when the long bar
  is clipped.
- Preview body is NEUTRAL (no display:flex centering) so validations match
  the real rendered layout.
- updatePreview and updateTarget in src/preview.js now use an IDENTICAL
  document template (a single renderDoc helper), so the same CSS renders the
  same way in both iframes.
- Every render gets a unique id (data-render-id on <html> + dataset on the
  iframe). The game only validates when the preview shows the latest id, so
  the answer is never checked against an outdated preview.
- Validators check geometry (positions, relative sizes, computed styles), NOT
  the exact CSS string and NOT exact pixel sizes, with generous tolerances.
- Full CSS starter code shown with `/* ?? ... ?? */` comments marking answers.
- Check Answer marks level completed, shows explanation + green Next Level
  button.
- The game intentionally teaches flexbox only: all remaining levels use
  display: flex, and the CSS Tags guide lists flexbox + box-model props.
- Level 6 (Responsive Flexbox Wrapping) keeps a grid alternate solution, but
  the flex answer comes FIRST so the target preview shows the flex layout.

LEVEL DATA FORMAT
-----------------
- Each level: id, title, description, hint, html, starterCSS, solutions[], validate
- Each solution: { css, explanation[], tip }
  - css: the complete CSS of the answer
  - explanation: array of { label, text } - label is the element/property
    name (e.g. "justify-content: center"), text explains what it does
  - tip: the main idea of the level, shown in a highlighted box
- The CSS Tags guide (cssTagsGuide export) is an array of
  { tag, group, summary, details, values, example } used by the CSS Tags
  modal: group builds the section titles, summary is the closed line and
  details + values + example are the expanded content.
